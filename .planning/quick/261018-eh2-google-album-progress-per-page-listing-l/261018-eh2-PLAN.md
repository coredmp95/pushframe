# Plan: google-album progress — per-page listing lines + tqdm on disk weight

## Objective

The venus incident (2026-10-18): `pushframe google-album nous` printed the
`Album:` header then went silent for many minutes (~1094 items in the album
'Nous': 4 listing pages with no output, then measure_disk_weight issuing one
sequential 1-byte Range GET **per photo** — with the tqdm dep already present
but unused on this path). The command is healthy; the UX is silent and
misleading. Add progress visibility without changing any behavior:

1. `enumerate_album(session, album_id, *, ..., progress: Callable[[PageTrace], None] | None = None)` —
   called once per completed page with the item count (+ retries), so the CLI
   can print `page N: M items` lines.
2. `measure_disk_weight(session, base_urls, *, show_progress=False)` —
   tqdm bar (dep `tqdm>=4.66` already in pyproject, used by aura.py/gsync.py).
3. `run_google_album` wires both (stderr-friendly prints, `--verbose` not
   required for the progress lines; the final summary output stays on stdout
   unchanged).
