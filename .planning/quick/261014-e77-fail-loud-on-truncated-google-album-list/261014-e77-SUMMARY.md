# Phase quick-261014-e77 Plan 01: Fail loud on truncated Google album listing Summary

A transiently tokenless full snAcKc page (the 2026-10-13 prod incident: 300 of 757 items accepted as complete, then relabelled "Videos skipped: 457") is now retried once with the same cursor, and a persisting truncation or any listing more than max(5, ceil(2%)) below the album metadata count is refused with a named SafeSyncError in every mode before any frame contact.

## What was built

**Task 1 (tracer) — enumerator + wiring (E77-1, E77-2 wiring)**
- `enumerate_album(..., expected_count=None)`: when given, a full page with no continuation token while the listing is short of `expected_count` is re-issued once (local per-enumeration counter, not the module-global null-payload `_retry_budget`). A tokened retry answer continues the walk (757 = 300+300+157, page_count 3). If still tokenless and the shortfall exceeds the tolerance, the partial listing is returned with `exhausted_cleanly=False` (no raise), so the existing `truncated_listing` gate fires. Short pages stay terminal and are never retried; a last full page within the video tolerance (600 vs metadata 602) is a clean end. `PAGE_SIZE` is read at call time.
- `listing_shortfall_tolerance(n) = max(5, (2n+99)//100)`, integer math.
- `run_google_sync` passes `expected_count=metadata_count`.
- Docstrings updated (module bullet for the 2026-10-13 transient, glued-bullet newline fixed, `AlbumListing`).

**Task 2 — SAFE-01 gate (E77-2, E77-3)**
- `SafeSyncError.listing_below_metadata(listed, expected)` with the specified message; `truncated_listing` gains a remedy suffix (leading text byte-identical).
- Pure `check_listing_trust(listing, metadata_item_count=None)`: order empty -> truncated -> below-metadata. Used by `run_google_sync_plan` (replacing the inline checks) and by `run_google_sync`'s pre-frame block (before `if aura is None`, so no login/download/frame read, in dry-run, --apply --yes and --scheduled).
- Link/id targets (AlbumSummary with `item_count` None) borrow the count from the listed album with the same `album_id`; the same `metadata_count` feeds the plan's videos line.
- `report.py` unchanged: `should_send('ERROR', 1, ...)` is True and the subject reads `FAILED — album metadata says 757 items ...` (pinned by a new test).
